MICROSOFT COMMERCIAL PERSONALIZATION
Targeting Decision Framework
Working draft
A reusable decision process

Should this customer receive a different experience?

If yes, why — and what should change?

This framework is designed so someone who was not part of the project can understand how to make a targeting decision in seconds.

01
Rule #1

Do not personalize just because data exists. Personalize only when a different response would meaningfully help the customer.

01
WARRANT

Is there a meaningful reason to personalize?

Different data does not automatically justify a different experience.

Would a different experience materially improve the customer’s next step?

Look for a difference in need, readiness, relationship, proof required, path, offer, or next action.

If the answer is “No,” the framework should stop here. Default is a valid outcome.
02
CONTEXT

What relevant context do we know?

Use only context that can materially change the decision.

03
NEED

What is the customer trying to accomplish now?

The same audience can have a different need in a different session.

Choose the current need.

Declared intent should usually be stronger than a broad inference for the current session.
04
EVIDENCE

What signals support the decision?

A signal is evidence — not a decision.

05
RESPONSE

What is the smallest meaningful thing that should change?

The goal is usefulness — not maximum complexity.

Select one or more response types.
